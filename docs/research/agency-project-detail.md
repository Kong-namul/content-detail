# 에이전시 프로젝트 상세 페이지 — 정보 작성 방식 리서치

- 작성일: 2026-11-26
- 조사 범위: 에이전시 16곳, 상세 페이지 31개 (해외 디지털 5곳, 해외 브랜딩 4곳, 국내 7곳)
- 목적: 프로젝트 상세 페이지에 **어떤 정보를, 어떤 순서로, 어떤 말투로** 적는지 정리하고, 상세 페이지 템플릿 4~5종의 근거로 쓴다.
- 표기: 원문 문장은 옮기지 않고 요약했다. 라벨·헤딩·짧은 태그라인만 원문 그대로 적었다.

## 0. 한 장 요약

1. **H1은 이름이다.** 해외 18페이지는 전부 클라이언트명 또는 프로젝트명이 H1이다. 크리에이티브한 문장은 H1 아래 한 줄이나 본문 첫 헤딩으로 내려간다. 국내는 이름 단독이거나 `감성 카피, + 프로젝트명` 2단 타이틀이다 (이모션, 바이널씨).
2. **모든 페이지에 있는 건 네 가지뿐이다.** 이름, 한 줄 프레이밍, 대표 비주얼, 소개 문단 1개 이상. 나머지는 전부 선택이다.
3. **메타는 위 아니면 아래다.** 상단 팩트시트(Work & Co, Basic/Dept, Wolff Olins, 바이널씨)거나 하단 크레딧(Instrument, Locomotive, fnt, 플러스엑스)이다. 스크롤을 따라오는 사이드 패널은 한 곳도 없었다.
4. **긴 글은 숨긴다.** Pentagram은 드로어, Collins는 모달, Wolff Olins는 More Info 펼침으로 본문을 접어 둔다. 미디어가 먼저 보이고, 글은 원하는 사람만 연다.
5. **성과 수치는 해외에만 있다.** 해외 9곳 중 6곳이 숫자를 보여준다 (Work & Co, Collins, Basic/Dept, Instrument, Koto, Wolff Olins). 국내 13페이지는 KPI 0건, 클라이언트 인용 0건, 상세 안 수상 표기 0건이다.
6. **국내 관습은 따로 있다.** 영문 헤딩 + 국문 본문, 라벨 없는 메타 한 줄, SI식 범위 태그(Renewal, Construction), 텍스트를 넣은 장문 이미지, 로마자 이름의 긴 크레딧, 목록 버튼.
7. **구조는 다섯 가지로 묶인다.** 갤러리형, 챕터형, 성과 도시에형, 에디토리얼 롱리드형, 국내 케이스형 (5장 참고). 이게 템플릿 후보다.

## 2. 상세 페이지를 이루는 정보 블록

- 해외: 클라이언트명 단독 (`Oura`, `Patagonia`, `Nubank`). 프로젝트 성격은 아래 한 줄이 설명한다.
- 국내: 프로젝트명 단독 (`Essenherb Brand Identity Renewal`, `Samyang Group 100th Anniversary Identity`) 또는 2단 타이틀. 2단 타이틀은 쉼표로 끝나는 감성 카피 한 줄 + 프로젝트명이다. 광고·보도자료 헤드라인 문법이다.
- 크기: 64~110px 대형이 많다. BKID만 16px로 작게 쓰고 이미지에 무게를 둔다.

### 2-4. 본문 서사 구조

| 패턴 | 섹션 순서 | 쓰는 곳 |
|---|---|---|
| 문제 해결형 | Challenge → Approach (또는 Idea) → Impact | Instrument, Basic/Dept, Koto Microsoft, ustwo i Paper |
| 테이크어웨이형 | Overview → 3 Big Takeaways (01~03, 각각 하위 기능 2~4개) | Work & Co |
| 결과물 챕터형 | Challenge → 결과물별 챕터 (그래픽 시스템, 사진, 일러스트, 디지털, 서브브랜드) → Launch → Outcome | Koto Nubank, Basic/Dept 워크스트림 |
| 브랜드북 순서형 | Strategy → Logo → Visual System → Application | 플러스엑스 |

**헤딩 계층** — Instrument Uber는 3단계를 쓴다: 단계 라벨(H3) → 큰 주장 문장(H4) → 작은 소주제 라벨 + 본문. Koto는 2단계: 챕터 라벨 + 3~6단어 헤드라인.

### 2-6. 미디어와 리듬

**텍스트와 미디어를 섞는 네 가지 리듬**

1. 교차형 — 텍스트 1블록, 미디어 1~2개 반복 (Instrument, ustwo, Basic/Dept, 바이널씨)
2. 몰아주기형 — 텍스트를 위에 다 주고 미디어 10~50개를 캡션 없이 연속 (Locomotive, Wolff Olins Blank Street, fnt, BKID)
3. 스테이트먼트형 — 미디어 스트림 4~8개마다 20~40단어짜리 큰 글씨 문장이 끼어든다 (Pentagram)
4. 챕터형 — 챕터마다 1문단 + 미디어 2~5개 (Koto, 플러스엑스)

**미디어 형식** — 풀블리드 이미지, 그리드 안 16:9, 2-up / 3-up, 루프 영상, 클릭 재생 영상, 디바이스 목업, 폰 화면 3~4개 가로 줄, 풀페이지 스크롤 캡처, 가로로 넘치는 갤러리 스트립 + "Explore the gallery", 모자이크 콜라주, 인터랙티브 데모(Koto), 브랜드 가이드 시트, 텍스트를 넣은 장문 이미지(펜타브리드, PC/모바일 세트 따로).

캡션은 거의 없다. 이미지는 설명 없이 이어지고, 설명이 필요하면 큰 스테이트먼트나 본문이 맡는다.

## 3. 카피 작성법

- **헤드라인**: 한 줄 프레이밍은 4~9단어. 국내 2단 타이틀의 카피는 쉼표로 끝낸다.
- **섹션 헤딩 세 가지**
  - 기능 라벨: Overview, Challenge, Results, PROJECT GOAL
  - 원칙·아이디어 구: "Progressive disclosure", "Storytelling that converts"
  - 감성 문장: "A game like no other", "The people are the magic"
  - 대부분 기능 라벨에 나머지 하나를 섞는다. 국내는 영문 헤딩 + 국문 본문이 기본이다.
- **문단 길이**: 영문 25~90단어 (2~4문장). 국문 100~300자 (1~3문장).
- **총 분량**: 80단어(Locomotive)부터 1,100단어(ustwo, Basic/Dept)까지. 갤러리형은 짧고, 롱리드형은 길다.
- **화자**
  - 1인칭 "we": Instrument, Koto, Locomotive, ustwo, Basic/Dept
  - 3인칭 에이전시명: Pentagram, Collins, fnt — 보도자료 톤
  - 스토리텔링: Wolff Olins — 일화로 시작
  - 국내: 합니다체 보고서 톤이 기본, 바이널씨 일부는 해라체 기사 톤
- **리드 여는 법**: 클라이언트 배경 / 문제 정의 (Instrument) / 수사적 질문 (Collins Arcane) / 일화 (Wolff Olins Bergdorf)

## 5. 구조 아키타입 다섯 가지 (템플릿 후보)

### A. 갤러리형 — 이미지가 이야기한다

- 사례: Locomotive, Pentagram, 스튜디오 fnt, BKID (Wolff Olins Blank Street 후반부)
- 골격: 태그 · 타이틀 · 연도 · 산업 → 히어로 + 짧은 태그라인 → 짧은 About (80~120단어, 또는 2단 문단) → 수상 목록 → 캡션 없는 미디어 10~50개 (가끔 큰 스테이트먼트) → 크레딧 → 다음 프로젝트
- 변형: 긴 글을 드로어·모달로 숨긴다 (Pentagram, Collins)
- 어울리는 프로젝트: 시각 아이덴티티, 제품 디자인, 공간

### B. 챕터형 — 결과물 단위로 나눠 보여준다

- 사례: Koto, 플러스엑스, Basic/Dept 워크스트림
- 골격: 풀블리드 히어로 → 타이틀 · 태그라인 · `분야 · 연도` → 인트로 2문단 → 화면 하단 고정 챕터 내비 → [챕터 라벨 + 3~6단어 헤드라인 + 1문단 + 미디어 2~5개] × N → Outcome (문단 + 숫자 타일 또는 콜라주) → Next up
- 어울리는 프로젝트: 리브랜딩 풀패키지, 다채널 캠페인

### C. 성과 도시에형 — 숫자가 먼저 나온다

- 사례: Work & Co, Collins, Basic/Dept (Results 상단 배치), Wolff Olins Blank Street (인트로)
- 골격: 컬러 밴드 위 타이틀 + 짧은 주장 → 히어로 → What We Did (라벨 왼쪽 · 내용 오른쪽) → Outcomes 큰 숫자 → Overview → 클라이언트 인용 → 수상 · 프레스 → 01~03 테이크어웨이 챕터 (하위 기능마다 미디어 1개) → 다른 프로젝트 목록
- 어울리는 프로젝트: 디지털 프로덕트, 이커머스, 성과가 분명한 프로젝트

### D. 에디토리얼 롱리드형 — 읽는 이야기

- 사례: ustwo, Wolff Olins Bergdorf, Instrument Uber
- 골격: 타이틀 + 서술형 부제 → 히어로 → 맥락 3~4문단 → 클라이언트 인용 → 이야기형 H2 4~6개 (기회 → 접근 → 과정 → 결과물 → 임팩트), 사이사이 2-up 이미지와 여러 목소리의 인용 → 마무리 인용
- 레이아웃 힌트: 본문은 오른쪽 반 칼럼, 인용은 왼쪽에 걸어 매거진 스프레드처럼 (Wolff Olins)
- 어울리는 프로젝트: 전략, 서비스·고객경험, 조직문화처럼 비주얼이 적은 프로젝트

### E. 국내 케이스형 — 라벨과 정의목록

- 사례: 이모션글로벌, 바이널씨, 펜타브리드
- 골격: `감성 카피,` + 프로젝트명 2단 타이틀 → 메타 한 줄 (클라이언트 · 연월 · 범위 태그) → 대형 리드 → PROJECT GOAL (포인트 3개) → DESIGN CONCEPT (KEYWORD / COLOR / ICON) → 문단 ↔ 풀폭 미디어 교차 → Credits 정의목록 → 사이트 링크 · 앱 다운로드 → PREV / NEXT + 목록
- 어울리는 프로젝트: 웹·앱 구축과 리뉴얼, 국내 클라이언트

## 6. 템플릿 설계로 가져갈 것

**모든 템플릿 공통 (필수)**

- 이름 (H1)
- 한 줄 프레이밍
- 대표 비주얼
- 소개 문단
- 메타: 클라이언트 · 연도 · 산업 · 업무 범위 (위치는 템플릿마다 다름)
- 다음 프로젝트

**템플릿에 따라 켜고 끄는 블록 (선택)**

- 성과 숫자, 인용, 수상 · 프레스, 사람 크레딧, 라이브 링크, 다운로드
- 챕터 내비, 큰 스테이트먼트, 본문 드로어 · 모달, 가로 갤러리 스트립

**리서치에서 본 함정 (제안)**

- 숫자 없는 성과 섹션: "전환율 상승을 기대한다" 같은 문장은 성과 블록이 아니라 본문에 둔다. 성과 블록은 숫자가 있을 때만 켠다.
- 텍스트를 이미지에 넣기: 국내에서 흔하지만 검색, 접근성, 번역이 안 된다. 템플릿에서는 HTML 텍스트로 쓴다.
- 라벨 없는 메타: 값만 나열하면 "2025.06"이 런칭일인지 계약일인지 모른다. 라벨을 작게라도 단다.
